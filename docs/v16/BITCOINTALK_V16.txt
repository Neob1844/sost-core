[size=14pt][b]What changes at #30,000[/b][/size]

To take part in the DTD Jackpot, a miner will need [b]all[/b] of the following:
[list]
[li]a valid SbPoW mining identity;[/li]
[li]at least [b]3 valid mined blocks within the previous 5,000 blocks[/b];[/li]
[li]a cryptographically linked SOST node identity ([tt]NODE_BIND[/tt]);[/li]
[li]verified node participation through periodic signed heartbeats.[/li]
[/list]

Your Jackpot probability is then [b]proportional to your real PoW contribution[/b] in the 5,000-block window (LINEAR weight). The DTD Jackpot has its own independent deterministic draw, [b]no cooldown[/b], [b]no anti-dominance[/b], a [b]100 SOST[/b] base, rollover up to the existing [b]500 SOST[/b] cap, and is paid from the existing historical reserve — [b]there is no new emission.[/b] If there is no eligible winner, it rolls over.

[size=12pt][color=red][b]Running more nodes does not give you more Jackpot tickets.[/b][/color][/size]
A node is a [b]requirement for participation[/b]; your actual PoW contribution determines your probability. Node = access. PoW = probability.

[size=14pt][b]How it works — in plain terms (with an example)[/b][/size]

The system does not "guess" anything. It [b]verifies cryptographic proofs that are recorded on the blockchain[/b]. The chain already knows who mined which blocks, with which mining key, which node key they linked, and whether that node has been sending valid signs of activity.

[b]1) A valid SbPoW mining identity[/b]
Every SOST block carries a [b]mining public key + a signature[/b]. So the chain can prove who produced it:
[code]miner  ->  mining private key  ->  signs the block  ->  mining identity (sost1ABC...)  ->  BLOCKCHAIN[/code]
You cannot just claim "I mined this block" — the chain can check the signature. This is a [b]cryptographic mining identity[/b]; it is not your name, IP, or physical computer.

[b]2) At least 3 blocks in the last 5,000[/b]
At a jackpot height (e.g. #30,186) the system looks back over the last 5,000 blocks and counts how many your identity signed. No report is needed — it just counts signatures:
[code]sost1AAA...  ->  #29,811, #29,945, #30,041, #30,100  =  4  (4 >= 3  -> OK)
sost1BBB...  ->  #29,930, #30,020                      =  2  (2 <  3  -> not eligible)[/code]

[b]3) A linked node identity (NODE_BIND)[/b]
There are two keys: a [b]mining key[/b] ("I am this miner") and a [b]node key[/b] ("I am this participating node"). A [tt]NODE_BIND[/tt] is a small transaction, [b]signed by the mining key[/b], that says "miner A authorizes node key N":
[code]NODE_BIND:  sost1AAA  ->  node_pubkey 03F8A9...   (signed by sost1AAA's mining key)[/code]
Any node verifies the signature and records the link on-chain. Note: this identifies a [b]node key[/b] bound to your mining identity — it does NOT identify your physical machine.

[b]4) Verified node participation (heartbeats)[/b]
Registering once is not enough — the node must keep proving it is following the chain. About every [b]288 blocks[/b] the node publishes a small signed proof:
[code]NODE_HEARTBEAT:  node_pubkey + epoch + recent-block reference + signature[/code]
Others check: signature matches the registered node key? epoch correct? the block reference matches the real chain? not already sent for this period? If all yes -> heartbeat valid. Because the [b]recent-block reference is not known until the chain reaches it[/b], heartbeats cannot be pre-fabricated — the node has to actually be following the chain.

[b]Full example — three miners[/b]
[code]MINER A:  SbPoW ok · 10 blocks/5000 · NODE_BIND ok · heartbeats ok   ->  ELIGIBLE, weight 10
MINER B:  SbPoW ok ·  5 blocks/5000 · NODE_BIND ok · heartbeats ok   ->  ELIGIBLE, weight  5
MINER C:  SbPoW ok · 30 blocks/5000 · NODE_BIND NO · heartbeats NO   ->  NOT ELIGIBLE[/code]
C mined the most, but did not meet the node requirement, so C is out. The draw is then:
[code]A weight 10  +  B weight 5  =  total 15
A ~= 66.7%     B ~= 33.3%[/code]

[b]How does any node know all this?[/b] It reconstructs everything by reading the blockchain alone — count SbPoW signatures over the last 5,000 blocks, find the NODE_BIND, find the valid heartbeats, then compute eligible/weight. [b]No central database, no trust in the user, no manual approval.[/b]

[b]An honest limitation[/b]
The system can prove "this node key participated correctly and was bound to this miner." It [b]cannot[/b] prove there is a distinct physical machine in a distinct place behind that key. That is why we call it [b]Verified Node Participation[/b], not "verified independent physical node". For the Jackpot this is fine, precisely because [b]more nodes add no weight[/b] — the node only grants access; your PoW sets the probability.

[size=14pt][b]A note from the developer[/b][/size]

[quote]
I am aware there have been several forks to fine-tune the system. From the very beginning it was stated that SOST is an [b]experimental[/b] project — it is a new kind of Proof-of-Work — but a [b]fully functional[/b] one, currently in [b]pre-market[/b].

Things are no longer like the early days of crypto, when you could list on almost any exchange. Today most of the large exchanges require capital and audit conditions that SOST does not have at this moment. So the system has to evolve on its own — now that it is almost entirely decentralized, with only the Singapore node left to activate — by listing on a venue better suited to our current, early stage, presumably [b]non-KYC[/b]. And there is an essential reason for that:

As far as it has been tested, the protocol works well, but it needs to be seen operating in a [b]real environment, inside an exchange[/b], to assess that neither its security nor its functionality is compromised.

This does not mean the protocol will succeed, or that we will not be delisted after a few months. It is one more step on this hard road, and it has to be taken. If it goes well, we will take the necessary measures to keep moving toward a [b]solid legal entity[/b] and to plan an [b]audit[/b] that meets current European and American standards.

But let us not fool ourselves: this is a tedious and challenging path, where things may work out or may not — and that has to be kept in mind.

— NeoB
[/quote]

[size=14pt][b]CORE ECONOMIC DESIGN — WHAT THE PROTOCOL DOES TODAY[/b][/size]

[code]
Blocks 0 – 24,999   (historical)     Blocks 25,000 onward  (in force)
  50% → Miner                          50% → Miner
  25% → Gold Funding Vault             50% → DTD distribution
  25% → PoPC Pool                       0% → Gold Funding Vault
                                        0% → PoPC Pool
[/code]

This is a consensus rule at every height: a block carrying the wrong split for its height is invalid.

The DTD distribution returns that half to active miners by a per-block draw. Since V15 the DTD draws on [b]every block[/b] (3-of-3). The older cadences — 2-of-3 bootstrap from #7,100, then 1-of-3 from #12,100 — ended at #25,000.

[b]The DTD is permissionless.[/b] No registration, no whitelist, no NODE_BIND, no heartbeats and [b]no PoPC bond[/b] — on mainnet the PoPC eligibility gate ships deactivated. Mining one valid block inside the recency window is what makes an address eligible.

[b]SOST is not backed by gold.[/b] There is no peg, no redemption right, no oracle in consensus and no stablecoin mechanic.

[size=14pt][b]HISTORICAL RECORD — GOLD FUNDING VAULT AND PoPC POOL[/b][/size]

[i]This section documents a mechanism that operated from genesis to block #25,000 and no longer receives emission. It is kept for auditability, not as a description of current behaviour.[/i]

From genesis until block #24,999, every normal block allocated 25% of the subsidy to the Gold Funding Vault and 25% to the PoPC Pool, enforced by consensus. On triggered lottery blocks from #7,100 those two shares went to the lottery winner or to the pending jackpot instead.

[b]What changed at #25,000 (V15).[/b] The non-miner half of every block is redirected to the DTD distribution. In the node's emission-transition branch both amounts are literally zero from that height on.

[b]What remains true.[/b] The vault and pool addresses still exist on chain and still hold what they received before V15. Every one of those coinbase outputs is publicly auditable in the explorer. Nothing new flows in, nothing was burned, and nothing was redirected into anyone's pocket: the DTD Jackpot progressively returns that accumulated reserve to active miners as a supply-neutral treasury spend — no new emission is created for it.

[b]PoPC.[/b] Proof of Personal Custody was implemented and documented but never became operationally active on mainnet, and the DTD never required it. Planned spend-side Gold Vault governance (the ≥90% miner-signalling supermajority over a 67-block window) was never activated either. Both are recorded here as project history.

[size=14pt][b]DTD JACKPOT V2 — WHAT CHANGES AT #30,000[/b][/size]

[b]Normal DTD[/b] keeps its payout, its every-block cadence, its uniform selection among eligible identities and its seed. What changes is who qualifies:

[code]
                    until #29,999                from #30,000
recency             mined in last 5,000          mined in last 288 blocks
                    (20,000 at jackpot heights)  (at EVERY height)
minimum             >= 1 block                   >= 1 block
cooldown            miner of last 6 excluded     same, but it YIELDS if
                                                 applying it would leave
                                                 nobody eligible
anti-dominance      >=10% of last 288 excluded   same, but ARMED only at
                                                 >= 11 distinct miners
[/code]

With few active miners those two gates used to exclude the very miners holding the chain up. They are now floors, not repeals: the cooldown applies whenever somebody else qualifies, and the 10% gate returns as soon as 11 distinct miners appear in the window.

[b]DTD Jackpot V2[/b] becomes a separate draw with its own winner. Eligibility, all required:

[list=1]
[li]a valid SbPoW mining identity;[/li]
[li]at least 3 valid mined blocks in the previous 2,016 blocks;[/li]
[li]an active NODE_BIND — a node key authorised on-chain by your mining key;[/li]
[li]node heartbeats, per the bootstrap schedule below.[/li]
[/list]

Weight = number of SbPoW blocks in the window, [b]linear[/b]. Splitting the same work across identities does not create weight, and running more nodes adds none: node participation is a gate, PoW is the weight. No jackpot cooldown and no jackpot anti-dominance, by design.

[b]The first draw, #30,186, requires ZERO heartbeats.[/b] NODE_BIND only becomes available at #30,000, so no epoch has completed and nobody can be excluded for lacking history. The requirement then ramps 1/1 → 2/2 → 3/3 and settles at the permanent 3-of-4 from #31,338. That ramp is one rule counting completed epochs — [b]not[/b] a second fork and not a second update.

Payout: base 100 SOST, rollover to a 500 SOST cap, paid from the existing historical reserve. [b]No new emission.[/b] Zero eligible participants means rollover, never an invented winner.

[size=14pt][b]HOW TO MINE[/b][/size]

Requirements: Linux x86_64, 8 GB RAM for mining (4 GB dataset + 4 GB scratchpad), CPU-only. A node alone needs ~500 MB.

[b]1 — Get the binaries[/b] (downloading is equally valid; compiling is optional)

[code]
mkdir -p ~/sost && cd ~/sost
for f in sost-node sost-miner sost-cli SHA256SUMS; do
  curl -fsSL -O "https://github.com/Neob1844/sost-core/releases/download/v16.2.3/$f"
done
sha256sum -c SHA256SUMS        # must print OK for all three
chmod +x sost-node sost-miner sost-cli
[/code]

Or build from source — this exact sequence was run from a clean clone and produced the published hashes:

[code]
sudo apt update && sudo apt install -y build-essential cmake git libssl-dev libsecp256k1-dev
git clone --depth 1 --branch v16.2.3 https://github.com/Neob1844/sost-core.git sost-src
cd sost-src
cmake -S . -B build -DSOST_ENABLE_PHASE2_SBPOW=ON -DSOST_TESTNET_FORKS=OFF -DCMAKE_BUILD_TYPE=Release
cmake --build build --target sost-node sost-miner sost-cli -j"$(nproc)"
cd build && sha256sum -c <(grep -E '^[0-9a-f]{64}' ../docs/v16/SHA256SUMS)
[/code]

The build directory must be named [tt]build[/tt] — the source path is normalised out of the binary, the directory name is not. A different compiler legitimately yields a different hash; cross-machine reproducibility is not claimed, but an official [i]downloaded[/i] binary must match exactly.

[b]2 — Create a wallet and label the mining key[/b]

[code]
umask 077
./sost-cli --wallet wallet.json newwallet
./sost-cli --wallet wallet.json getnewaddress "my-miner"
chmod 600 wallet.json
# BACK THIS FILE UP, off this machine. The key in it receives every block you mine.
[/code]

[b]3 — Choose YOUR OWN RPC password[/b]

There is no universal SOST RPC password. You pick one for your own node; the miner authenticates to it. It is not your wallet passphrase, and it never belongs on a command line, where every local user can read it with [tt]ps[/tt].

[code]
mkdir -p ~/.sost && umask 077
openssl rand -base64 30 > ~/.sost/rpc.pass
chmod 600 ~/.sost/rpc.pass
[/code]

[b]4 — Start the node[/b]

[code]
cp ../genesis_block.json .
./sost-node --genesis genesis_block.json --chain chain.json \
  --connect seed.sostcore.com:19333 \
  --rpc-user myuser --rpc-pass-file ~/.sost/rpc.pass \
  --profile mainnet --p2p-enc on
[/code]

Optional fast start: [tt]curl -o chain.json https://sostcore.com/bootstrap-chain.json[/tt] before launching.

[b]5 — Start the miner[/b] (in a second terminal, once the node is synced)

[code]
./sost-miner \
  --wallet wallet.json --mining-key-label "my-miner" \
  --genesis genesis_block.json \
  --rpc 127.0.0.1:18232 \
  --rpc-user myuser --rpc-pass-file ~/.sost/rpc.pass \
  --blocks 999999 --max-nonce 500000 \
  --profile mainnet --realtime --threads 8
[/code]

[tt]--wallet[/tt] + [tt]--mining-key-label[/tt] select the key that [b]signs[/b] your blocks (SbPoW); the payout address is derived from it. Do not use [tt]--address[/tt] instead: your V16 Jackpot eligibility and your NODE_BIND both depend on that signed identity.

[b]6 — Check[/b]

[code]
./sost-cli --rpc 127.0.0.1:18232 --rpc-user myuser \
  --rpc-pass-file ~/.sost/rpc.pass --wallet wallet.json getbalance
[/code]

Coinbase outputs mature after 1,000 blocks (~7 days), so a fresh balance shows as immature first. Full guide: [url=https://sostcore.com/sost-quickstart.html]quick start[/url] · [url=https://sostcore.com/sost-mine.html]mining guide[/url]. Never paste a private key, seed phrase or wallet file anywhere.

[size=14pt][b]CONVERGENCEX v2.0 — TECHNICAL SUMMARY[/b][/size]

ConvergenceX is a Proof of Irreversible Convergence algorithm. Each attempt solves a linear system A(x)=b and proves the solution sits in a stable basin — small perturbations converge back to the same attractor — verified by deterministic stability checks.

[code]
PROBLEM     A(x) = M^T(Mx) + λx = b   — n×n SPD system
DIMENSION   n = 32                     (CX_N)
ROUNDS      100,000 per attempt        (CX_ROUNDS_M)
λ           100                        (CX_LAM) — unique solution
LR SHIFT    18 → learning rate 2^-18   (CX_LR_SHIFT)
DATASET     4 GB SplitMix64-indexed, O(1) per value
MEMORY      mining ~8 GB (4 GB dataset + 4 GB scratchpad); node ~500 MB
PROGRAM     256 ops per block (MUL/XOR/ADD/ROT/AND/OR/NOT/SUB) — changes every block
TRANSCRIPT  V2: segment commitments + sampled round witnesses
[/code]

From V11 Phase 1 (block 7,000) the dataset index is state-dependent — [tt]dataset[state_lo % size][/tt] derived from the previous round's SHA-256 state, instead of a predictable [tt]r % size[/tt].

[b]SbPoW[/b] (V11 Phase 2, live since #7,100): every block header carries a public key and a signature over the PoW commitment, and the coinbase must pay the address derived from that key. Post-hoc coinbase relabelling is impossible. SbPoW is the protocol's only anti-pool defence — per-instance Memory-Lock was evaluated and rejected because it penalises small miners proportionally more than large rigs.

Chain selection is by cumulative work, [tt]work = floor(2^256 / (target + 1))[/tt], with atomic reorg and rollback on failure.

[b]Open-source and attribution.[/b] ConvergenceX has been public since genesis. Projects that use, reference or derive from it are asked to identify ConvergenceX as the underlying PoW design and, when practical, display the logo: [url=https://sostcore.com/convergencex-logo.png]convergencex-logo.png[/url]
